B.1 Why ANSI SQL

Every listing in this book uses ANSI SQL, the standard defined by ISO and IEC. The book is about patterns, and a pattern is the same on every engine. Engine-specific SQL ties each listing to one product and hides the pattern behind its syntax.

Most analytical engines support the parts of the standard that the book uses: joins, window functions such as ROW_NUMBER and LEAD, common table expressions with WITH, and UNION ALL. Where an engine differs, the differences are small and local. The table below lists the ones that matter for the listings.

B.3 Conventions in the listings

Keywords are in upper case, and names are in lower case with underscores, except in chapter 13, which follows anchor modeling's own naming convention.

Listings show the pattern, not production code. They leave out error handling, batching, transaction control, and performance hints, which differ by engine and team.

Dates use half-open intervals. A row is valid from valid_from up to, but not including, valid_to, and the current row ends on 9999-12-31, as section 4.3 explains.

Loads are idempotent where possible. Most insert statements check with NOT EXISTS that the row is new, so a repeated load adds nothing.
