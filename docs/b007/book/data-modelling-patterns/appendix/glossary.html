Appendix A

Glossary

Every term that the book defines, in alphabetical order, with the chapter or section where it is introduced.

TermMeaningWhere
Accumulating snapshotA fact table with one row per process instance, updated at each milestone.7.2.2
ActivitySomething an entity did at one moment, stored as one row of an activity stream.14.1
Activity streamOne narrow, time-ordered table of all activities of one kind of entity.14.2
Additive measureA measure that can be added up across every dimension.7.2.1
Aggregate tableA table of totals stored in advance, built from a base fact.8.8
AnchorAn anchor modeling table that holds only identities.13.2
Annex tableA CRT anchor table that holds assertions: positor, positing time, and reliability.13.6.3
As-of queryA query for data as it was at a point in time, on one clock or both.4.5
AssertionA positor's opinion of a posit: assert(P, p, α, T).13.6.2
Atomic grainThe finest grain that a source provides.3.3
Audit dimensionA dimension that describes the load that produced each fact row.8.7
BitemporalKeeping both business time and record time on every row.4.4
Bridge table (dimensional)A table between a fact and a dimension for many-to-many relationships, often with weights.8.3
Bridge table (Data Vault)A query helper that stores a path across several links.12.8
Build and run effortThe thirteenth measure: tables, load code, and learning needed.5.5
Business keyThe identifier that the business uses, such as a SKU. Also natural key.3.4
Business key collision codeA short code added to a key so that keys from two sources cannot collide.11.2
Business timeWhen something was true in the real world. Also valid time.4.1
Business vaultVault tables built by business rules over the raw vault, with versions.12.9
CardinalityHow many members of one side of a relationship connect to the other side.3.5
Changing timeIn anchor modeling, when a value took effect.13.6.1
Chasm trapWrong totals from joining two facts through a shared dimension.15.2
Cohort activityThe activity that decides the rows of an activity schema query.14.4
Column-oriented storageStorage that keeps each column separately, so queries read only the columns they need.10.1
Computed satelliteA business vault satellite that holds the result of a rule.12.9
Concurrent-reliance-temporal (CRT)The anchor modeling setting that records sources, reliability, and both clocks.13.6
Conformed dimensionA dimension shared by several facts, with the same keys and meaning.7.7
Conformed factA measure with one definition everywhere it appears.7.7
Crypto-shreddingDeleting personal data by destroying the key that encrypts it.12.11
Data modelThe decisions that turn raw source data into data that answers questions.1.3
Data warehouseA separate store built for analysis of a company's data.1.1
Degenerate dimensionA dimension value with no other attributes, stored on the fact row.7.4
DenormalizationCopying values into a table on purpose, so queries need fewer joins.3.7
Dependent data martA mart built only from the integrated core.6.1
Dereferencing setThe set of identity and role pairs that a posit is about.13.6.1
DimensionThe context of a fact: who, what, where, when, and how.3.2
Drilling acrossTotaling each fact separately, then joining the results on conformed dimensions.7.6.1
Driving keyThe side of a link that defines when a relationship has changed.12.2
Durable keyA key that stays the same for one entity across all its versions.8.1
Effective datingGiving each row the start and end of the period when it was true.4.3
Effectivity satelliteA satellite on a link that records when the relationship was valid.12.2
FactThe record of an event or state that carries measures.3.2
Factless fact tableA fact table that records that something happened or was true, with no measure.7.2.2
Fan trapWrong totals from joining a measure to the many side of a relationship.15.2
Fan-outA join that multiplies rows, silently changing sums.10.5
Feature tableA wide table at the grain of a prediction, used for machine learning.10.6
FunnelA chain of activities, each appended as "first after" the previous one.14.5
Galaxy schemaSeveral fact tables that share conformed dimensions. Also fact constellation.7.7.1
Ghost recordA dummy satellite row that lets PIT queries use inner joins.12.7
GrainWhat one row of a table means.3.3
Hash diffOne hash over all descriptive columns of a satellite row.11.5
Hierarchical linkA link from a hub to itself that stores parent and child.12.4.2
Hierarchy bridgeA table of every ancestor-descendant pair in a tree.8.4
Historized attributeAn anchor attribute that keeps one row per value, with its changing time.13.2
HubA Data Vault table of unique business keys for one concept.11.1
IdempotentSafe to run twice, with the same result as running once.11.6
Inferred memberA placeholder dimension row created when a fact arrives before its dimension.7.5.1
Information martA star, wide table, or summary built from a vault for people to query.12.10
Insert-only storageStorage that never changes a row and adds a new row for every change.4.6
Join eliminationAn engine skipping a joined table that a query does not need.13.5
Junk dimensionA dimension of combinations of small flags.8.6
Key cross-referenceA table that maps each source key to one core key.6.4
KnotAn anchor modeling table of a small shared set of values.13.2
LinkA Data Vault table that records a relationship between hubs.11.3
MeasureA number in a question, such as net sales or hours worked.3.2
Mini-dimensionA small dimension of combinations of fast-changing attributes.8.2
Multi-active satelliteA satellite that holds several valid values per key at once.12.1
Non-historized linkA link for events that never change, with values in the link row.12.5
NormalizationSplitting tables so that each fact is stored in exactly one place.3.6
OLAP, OLTPAnalytical processing, and the transaction processing that runs a business.1.1
One big tableA single wide table with every attribute copied onto every row.10
Operational data storeAn integrated, current, frequently refreshed store without history.6.7
OutriggerA small table that a dimension points to.8.6
PartyAny person or organization that the business deals with, with roles such as customer.6.5
Passive integrationLoading keys for one concept into one hub before anyone matches them.11.2
Periodic snapshotA fact table that records a state at regular intervals.7.2.2
Persistent staging areaAn append-only copy of every source extract, with load times.1.4
Point-in-time table (PIT)A query helper that stores, per key and date, which satellite rows were valid.12.7
PositA statement: a dereferencing set, a value, and a changing time.13.6.1
Positing timeWhen a positor held an opinion, usually when the warehouse recorded it.13.6.2
PositorThe source that holds an opinion in an assertion.13.6.2
Puppini bridgeThe central bridge of a unified star schema.15.1
Record sourceThe column that names the system and table a row came from.11.1
Record timeWhen a database learned something. Also transaction or system time.4.1
Record-tracking satelliteA satellite that records that a key was present in a load.12.3
Reference tableA small lookup table, such as minimum wages by city.12.6
ReliabilityA number from −1 to 1 for a positor's certainty. Zero is a retraction.13.6.2
Role-playing dimensionOne dimension used in several roles in one fact.8.5
Same-as linkA link from a hub to itself that records which keys are one entity.12.4.1
SatelliteA Data Vault table of descriptive values for one hub or link, with history.11.4
Semi-additive measureA measure that adds up across some dimensions but not over time.7.2.1
Slowly changing dimension (SCD)A dimension with a defined rule for each kind of change, numbered by type.8.1
Smart keyA key that packs meaning into its value.3.4
Snowflake schemaA star whose dimensions are split into normalized chains.9.1
Stage layerThe Data Vault layer that computes keys, hashes, and load metadata once.11.6
Star schemaA fact table with denormalized dimension tables around it.7
Status-tracking satelliteA satellite that records when a key disappears from or returns to a source.12.3
Surrogate keyA key that the warehouse creates, with no meaning outside it.3.4
Temporal joinA join on time order, such as last before or first in between.14.4
TieAn anchor modeling table that holds a relationship between anchors.13.2
Transaction fact tableA fact table with one row per event, never updated.7.2.2
Unit of workA set of keys that appear together in one event and stay together in one link.11.3
Weighting factorA share on a bridge row that keeps many-to-many totals correct.8.3
