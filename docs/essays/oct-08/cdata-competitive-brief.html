CData: From Connectors to the AI Gateway

What CData sells, how it is built, and where it competes

CData is a connector company moving up the stack into the AI control plane. Its moat is a decade of drivers that make hundreds of SaaS apps, databases and ERPs look like SQL tables. Everything it now sells, from managed MCP to a context engine to model routing, sits on that relational core. Since 29 September 2026 it describes itself as the AI gateway between AI and the systems that run the business.

A note on bias: the author builds data platform software in an adjacent market. This page describes CData on its own terms and argues for no vendor, including his own. Sentences tagged Our read are judgement, not documented fact.
Who this is for: product, engineering and sales leads who need a fast, sourced picture of CData. Sellers will get most from sections 2, 5 and 6. Architects should start with section 3 and section 7. It isn't a product evaluation; nobody here has run CData in production.

3 · Products and architecture

one connector core, several front doors

Four product lines share one connector core: Drivers (ODBC, JDBC, ADO.NET, Python, SSIS), Replication (Sync, Arc, DBAmp), Embed for OEM, and Connect AI, the managed platform renamed from Connect Cloud in September 2025. The diagram shows Connect AI as layers, from consumers down to the sources it reads.

Reading the layers from the bottom up, the table gives what each one does and where the claim comes from.

LayerWhat it isEvidence
Front doorsMCP for agents, ODBC/JDBC for BI tools, REST/OData for apps, and a virtual SQL Server (TDS) endpoint. MCP offers about 10 generic tools plus source tools, custom SQL tools and per-use-case toolkits. The query tool is SELECT-only and writes go through dedicated tools. Generic tools can't delete; Salesforce, Slack and OneNote source tools can.Release notes. Tool count unconfirmed: CData said 9 in December 2025; a docs-based count gives 11.

GovernancePer-user passthrough identity, additive access roles, PII masking, a query-level audit log, and kill switches per user, connection or account.Pricing page, roles docs
FederationCData's own Query Federation driver by default, with the Data Virtuality engine opt-in per account. Adds derived views, a cache in a customer-owned Postgres, and an on-prem gateway for SAP and SQL Server.Docs index. That the Data Virtuality engine is built on Teiid is unconfirmed.
Connector coreEvery source is modelled as relational tables. Each driver carries a SQL-92 engine that pushes down what the source supports and computes the rest locally.Driver architecture post

Our read Two query planners over one connector library is integration debt. The MCP discovery tools mirror JDBC metadata calls, so agents see a database catalog, not business concepts. The docs imply, without stating it, that agents read retrieved context and still write their own SQL against raw tables. That makes the context layer guidance an agent reads, not a semantic layer that executes definitions. The marketing promises more: a graph that learns from corrections, query patterns and Slack or Teams, with changes approved as diffs.

CData says Connect AI is not a replacement for catalog platforms and imports existing semantic models instead. Our read Watch it anyway. Today the context store holds imported metrics and hand-written glossary entries, but if teams start writing definitions there, it competes with semantic layers.

6 · Positioning and competitors

four fronts at once, which is both the pitch and the risk

CData sells three things: neutrality (no warehouse to fill, no favoured model), depth on hard systems like SAP and NetSuite, and write-back that is checked against each system's own rules. Adobe is the showcase. Futurum's Brad Shimmin reads the Gateway as CData moving from background drivers into the runtime governance tier.

Futurum names the hyperscalers, MuleSoft, Boomi and LLM proxies. The other names are our read.

Buyers' reviews will probe weak spots. Access roles only add permissions, and caching works only with shared authentication (roles, caching). Unverified reports add that workspace access overrides source permissions, that per-user passthrough doesn't work with OData, and that queries cap at 100 per user per minute. Check these before quoting them. Our read Pricing by source and seat makes the multi-source agent CData advertises expensive on self-serve plans. Many connectors added in mid-2026 look like lighter, profile-based connectors, so depth likely varies more than the headline count suggests.

The roadmap is partly stated. CData lists Databricks and Snowflake catalog integration as near-term on its context engine page. Our read The Gateway moves toward general availability, with news likely at its Foundations event on 5 November 2026. Human approval steps and rollback for agent writes come next, because security teams won't approve write-back without them, followed by more packaging for regulated industries and possibly another acquisition.

7 · Versus Denodo and Starburst

same promise, different engines underneath

All three put a virtual SQL layer over data that stays where it is, and all three now serve it to agents over MCP. The difference is what sits underneath: Starburst is a query engine, Denodo a modelling layer, CData a connector library.

CDataDenodoStarburst
Core assetHand-built connectors, mostly SaaS apps and ERPsLogical data model and optimizer over databasesTrino, a distributed SQL engine
Sweet spotLong tail of apps: Salesforce, NetSuite, SAP, GongCompany-wide virtual semantic layerLarge analytical queries over the lakehouse
WritesGoverned writes back into source appsWrites through some views; mostly read in practice (our read)Read-only over MCP
DeploymentManaged service first; drivers self-hostedCustomer-run, also cloudSelf-managed, or Galaxy as a service
Who builds the modelSchemas ship with connectors; context is retrieved text, metrics only by importData architects, with AI-suggested joinsData teams publish data products
MCP statusManaged platform since September 2025Native MCP in 9.4; Bedrock AgentCore integration, May 2026MCP server exposing data products

CData competes head-on with Denodo, because both now pitch a semantic layer to agents. Our read The Data Virtuality acquisition also puts CData into the same virtualization tenders. On semantics Denodo is ahead today, because its views execute definitions while CData's context is text the agent reads. CData's edge is reach into SaaS apps. It more often complements Starburst: Starburst handles lakehouse scale, while CData handles SaaS data and agent write-back.

Lakehouse fit confirms the Starburst point. CData's docs list no Iceberg or Delta connector, and the Parquet connector was removed in July 2026 (release notes), so CData reaches lakehouse data only through a running warehouse. In reverse, Databricks can query CData as a virtual SQL Server through Lakehouse Federation. Our read Every user then shares one stored token, lineage stops at CData, and large joins pull whole SaaS tables through rate-limited APIs. The diagram shows the pattern that follows.

This is CData's two-mode pitch in practice. Live access gets it in the door, and replication through Sync carries the heavy work.
